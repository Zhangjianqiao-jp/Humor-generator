# 评审校准及失效类型复核（2026-10-18）

## 生成候选小试的三对不一致

两对方法胜负反转（nycc_886、nycc_562），一对从 unjudgeable 变为偏好（nycc_742）。nycc_886 有一条 JSON preference=A，但理由末尾明确表示 B 更好，构成字段与理由矛盾。因此 schema_valid 只检查格式/枚举，不等于判定自洽。没有擅自根据理由改写标签，原记录保留。

## 已知排序校准

复用五个历史校准样本：562、691、859、593、549，逐一确认属于当前 homer_pretrained_7b_bridge_362/train.jsonl，不属于 validation/test。验证校准文件 SHA256 与历史 manifest 一致，并从原始 CSV 核对两个 caption 和均分。对每对执行两种顺序，再加入两条相同 caption 控制。评审提示、模型和参数与前次小试相同，不因结果修改。

- 12/12 返回格式有效。
- 人工高分候选被选中 6/10 次；这里十次展示来自五对，不是十个独立样本。
- 五对中三对顺序一致：两对均选高分、一对均选低分；另两对胜负反转。
- 相同 caption 控制 2/2 正确判平局。

原始人工排序是在漫画条件下收集，本次评审只有自动描述；所以 6/10 是跨条件一致性，不是通用“评审准确率”。小样本、清晰分差校准也不代表模型生成的接近质量候选。存在校准漫画与当前训练诊断漫画重叠；只用于探索，不是独立评估。

## 决策

暂停扩大当前描述式自动评审，不把标签当质量真值，不根据这套评审挑最优 latent 方案。保留 GPU 接口诊断；下一步质量评价需补充原图条件或独立人工偏好，再复核顺序与字段/理由一致性。改提示或换评审应记录新版本、用另组非 test 校准样本验证，不能只反复调到这五题通过。

本地原始材料 `results/preflight/v35_effectiveness_20261017/judge_calibration_probe/`；PR 仅存 `blind_judge_calibration_validation.json` 汇总与哈希。未修改任何既有评分记录。对齐 GPU 作业仍为 7103017，未重复提交。

参考：[Zheng et al., Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena, NeurIPS 2023](https://arxiv.org/abs/2306.05685)。论文支持评审偏差诊断，不保证当前模型和任务的可靠性。这里的矛盾和一致性数字来自本地真实调用记录。
