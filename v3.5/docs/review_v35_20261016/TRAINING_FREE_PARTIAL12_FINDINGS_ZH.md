# 无训练接口：前三批真实 GPU 结果（12/16，探索性）

## 证据范围

作业 7102101、7102269、7102275 的调度器 EXIT CODE 均为 0。三批各 60 条，共 180 条输出；固定训练集 12 个 cluster，尚有第四批作业 7102615 未完成。不得当作完整 16 样本结果或测试集结论。证据哈希见 `training_free_partial12_analysis.json`。

## 评分缺陷与修正

全部 60 条恢复输出都使用 Markdown JSON 围栏；直接 json.loads 因此全部失败。原严格指标保留，不能将零分解释成内容全部丢失。新增事后、次要内容指标：只移除整个输出最外层的一组 json/无语言代码围栏，不提取嵌在解释中的 JSON、不修复内容。对所有组使用同一规则；单独标注 posthoc，不能伪装成预注册指标。

| 条件 | 实体集合一致 | 路径一致 | 完整计划一致 | 说明 |
|---|---:|---:|---:|---|
| text_plan | 12/12 | 12/12 | 11/12 | 一例 conflict 被转换成字符串列表 |
| exact_embeddings | 12/12 | 12/12 | 11/12 | 与文本结果一致 |
| soft_top64_replayed_plan | 0/12 | 0/12 | 0/12 | 全部返回空对象 |
| norm_hidden_replayed_plan | 0/12 | 0/12 | 0/12 | 全部返回空对象 |
| no_memory | 不适用 | 不适用 | 不适用 | 12/12 正确返回空对象 |

text_plan 唯一严格内容不一致为 nycc_562：conflict 原值是带编号的字符串，输出变成两个字符串组成的列表。此例首先是结构转换，不足以认定语义丢失；不追加特例自动给分。

## 生成控制与解释

text_plan 和 exact_embeddings 的 24/24 个同 seed caption 完全一致；记录的前向接口控制也通过。其余各组格式通过分别为 no_memory 24/24、soft 24/24、norm_hidden 23/24。格式正确不代表幽默好。文本相对 no_memory 的全部 caption 不同，也不代表文本更好；仍欠盲评。

两个连续方案在该提示下均不输出计划字段，是接口可读性失败的直接证据；不是所有 latent 方法无效的证据，也不能排除表示对 caption 的其他影响。当前 recovery 指令允许无计划时输出空对象，结果可能包括模型未将连续片段识别为计划的情况。不要将其直接解释成隐藏表示的信息论互信息为零。

## 对 method 的决策

1. 暂不扩大 bridge 训练；先完成第四批固定实验。
2. 下一组使用已备好的六组 StateBridge-inspired replay 对比，检查坐标对齐是否能改善可读性；同一文本内容、长度、任务和种子，不混入压缩收益。
3. 如对齐仍返回空对象，再单独诊断发送端提示/接收插入位置和任务指令，而不是边跑边改某一组。
4. 如果文本计划未在盲评中改善幽默，则即使 latent 能完美恢复计划，也不能解决上游计划质量问题。计划恢复与幽默收益是两个不同门槛。
5. 保留训练式桥接作为后续候选，前提是训练目标能验证利用计划，并与匹配的文本训练基线比较。

## 文献对应

[CIPHER, ICLR 2024](https://arxiv.org/abs/2310.06272) 提供概率加权 embedding 通信先例；本实验 top64 teacher-forced replay 不等于原算法，不能用此次失败否定其论文。

[StateBridge](https://arxiv.org/abs/2608.13317) 针对 hidden 到输入嵌入空间的错配提出无训练对齐，是下一步候选；其论文结果不能替代本项目 GPU 验证。我们使用同消息 token 作为对齐参照，也不据此宣称连续消息含有文本之外的信息。
