# 无训练接口的数学诊断与可识别结论

## 当前状态

上一轮已实现脚本、提交作业并运行串行监控，属于实际进展。本轮核验 7102101 仍 QUE；没有生成结果。此次不更改排队实验，不扩展精度支线；检查数学定义和结果解释。

## 1. 重新编码计划不能凭空增加计划信息

固定骨干参数 θ、共享描述 D，已选计划 P，通信 Z=fθ(P)，目标 caption Y。因为 Z 是 P 的确定性函数，条件数据处理不等式给出

    I(Y; Z | D, θ) <= I(Y; P | D, θ).

这是关于当前“文本计划重编码”路线的推导，不是对所有潜在通信的否定。发送者若保留生成计划之前的额外内部状态 H，H 不一定是 P 的函数，需另建比较。

因此当前合理假设是：接收者更容易利用某种表示，或接口带来有益归纳偏置；不能声称从已经生成的文本中恢复了此前解码丢弃的全部信息。更多浮点数/更多比特容量不等于更多与 Y 有关的信息。

## 2. 当前 soft replay 与已选 token 不是同一信息

设计划 token 为 p1,...,pL，固定 header 为 c。

    πi(v) = Prθ(v | c,p1,...,p{i-1})
    zi = Σv∈Top64(πi) πi(v)/mass64(πi) · E(v).

当前脚本确实使用 t−1 logits 预测第 t 个 token，索引没有错；但这说明 zi 没有观察 pi。整个 Z1:L 最多依赖 p1:L−1。相同长度、相同前 L−1 token 而末 token 不同的两条消息，必然得到相同 soft 前缀。

本计划 JSON 最后 token 可能只是闭括号，所以这个严格反例不等于本数据损失了关键笑点；它否定的是一般性的“完整保留已选计划”说法。更早 token 的信息可以经后续预测分布传入，但不保证能逆向恢复。

该实验应解释为“条件分布混合 vs 已选计划文本”的诊断，不能声称仅改变了消息编码且信息无损。原始 CIPHER 的自由生成通信机制也不等于本 teacher-forced replay。

## 3. 概率加权 embedding 一般不可逆

E 为 V×d 词表 embedding 矩阵，概率向量 π∈simplex(V)，z=Eᵀπ。若 V>d+1，则增广矩阵 [Eᵀ;1ᵀ] 有非平凡零空间。可取非零 u 满足 Eᵀu=0、1ᵀu=0；对足够小的 ε 和内部概率点 π，π±εu 是不同合法分布，生成相同 z。

故即使不截断 top-k，加权向量也不一般保留完整词表分布。最简单反例：E=(-1,0,1)，π=(1/2,0,1/2) 与 q=(0,1,0)，二者都映射为 0。

此为线性代数事实，不否定该接口在任务上的实用价值；训练/无需训练方法都应以接收者利用和任务质量验证。

## 4. top-k 与向量尺度是两个独立因素

令被舍弃概率质量 δ=1−ΣTopk π，所有 embedding 范数 <=R。全词表均值 z 与 top-k 重归一化均值 zk 满足

    ||z−zk|| <= 2Rδ.

推导：z=(1−δ)zk+δztail，所以差为 δ(ztail−zk)。这个界只能约束输入向量，不提供经过多层非线性模型后的质量保证。当前代码只记录真实 token 在 top64 的覆盖率/概率，未记录 δ；不得把覆盖率等同于保留概率质量。

另由三角不等式，||Σπv E(v)|| <=Σπv||E(v)||；不同方向可能相消为零。soft 表现弱可能同时涉及语义混合与输入范数降低，不能只归因于信息不足。后续如增加范数匹配 soft 对照，应独立版本、同样样本，不在本轮结果后悄改原条件。

## 5. 直接 hidden-state 的限制

当前 hi 看到 pi，和 soft 的 πi 观察范围不同。norm-hidden 使用 ||E(pi)|| 做尺度参照，这包含已选 token 的一个标量信息，且范数校准不解决方向/坐标对齐。不能将其与 soft 的差异全部归因于“hidden 比概率强”。这也不是 StateBridge 对齐方法。

下一轮若比较对齐接口，应同时给出纯文本、未对齐 h、对齐 h，并披露是否使用对应 token embedding 做参照。正交变换只保持相应空间的几何，不自动证明语义可读；白化/反白化/词表锚定也不是整个流程都正交。

## 6. 恢复与幽默必须解耦

逐字复制成功是可读性的强证据，但不是幽默质量的充分条件；逐字复制失败也不是保留任务有用信息的必要否定。特别是长 conflict 的 JSON exact match 会混入格式、截断和同义改写。

后续分析分四层：

1. 工程：token embedding 控制、输出有限、格式、是否到达 token cap。
2. 表示：实体集合/路径顺序/冲突两个脚本的独立恢复；JSON exact match 作为严格辅助量。
3. 利用：matched 与 no-memory 的 caption 差异、计划支持程度；换计划是否改变相应内容。
4. 质量：图片级盲评幽默/贴合，不能用解释长度、恢复率、NLL 或是否变词替代。

no-memory 被明确要求返回 {}；它 exact-plan-recovery=0 是符合预期的，必须同时报告“无计划时按指令返回空对象”，不能当作模型不会恢复信息的负证据。

## 7. 当前五组可以与不可以回答的问题

| 比较 | 可以回答 | 不可以回答 |
|---|---|---|
| text vs no-memory | 该提示和描述下原计划的增量价值 | 单独证明所有 HOMER planner 有效/无效 |
| text vs exact embedding | 相同序列的输入接口行为是否一致 | latent 推理优于文本 |
| text vs soft replay | 该截断条件分布变体能否支持任务 | 原始 CIPHER 的严格复现；无损通信效果 |
| text vs norm-hidden | 冻结重编码 hidden 直接注入的可用性 | StateBridge 对齐是否有效 |
| 任意两组的 exact recovery | 严格内容复制的差别 | 幽默收益、语义恢复完整性 |
